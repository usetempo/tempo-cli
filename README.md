# Tempo CLI

Git hooks that detect AI tool usage and associate supported session file paths with commits. Detection runs locally; an optional API token enables attribution uploads.

## How it works

Tempo CLI checks session file matches first, running processes next, and supported commit-message markers last. Fallbacks are applied separately for each tool:

| Strategy | Confidence | How it works |
|----------|-----------|--------------|
| **Session file matching** | High | Extracts file paths from Claude Code and Codex JSONL, Copilot Agent JSON, Cursor SQLite sessions, and Aider history, then intersects them with committed files |
| **Process detection** | Medium | Checks for running Claude Code, Cursor, Copilot, Codex, or Aider processes on macOS and Linux when no file match exists for that tool. A running process does not prove that it changed the commit |
| **Git trailers** | Medium | Checks supported `Co-Authored-By` trailers and Aider commit-message patterns when no stronger signal exists for that tool |

## Install
Supported platforms: macOS and Linux (Intel & ARM).

**Homebrew:**

```sh
brew install usetempo/tap/tempo-cli
```

**Go:**

```sh
go install github.com/usetempo/tempo-cli@latest
```

## Quick start

```sh
# Optional: configure attribution uploads
tempo-cli auth <your-token>

# Install hooks in your repo
cd /path/to/your/repo
tempo-cli enable

# Verify detection works
tempo-cli test

# Attribution runs automatically after each commit.
```

## Commands

| Command | Description |
|---------|-------------|
| `tempo-cli enable` | Install post-commit and pre-push hooks |
| `tempo-cli disable` | Remove Tempo hooks (preserves other hooks) |
| `tempo-cli auth <token>` | Save API token for Tempo cloud |
| `tempo-cli status` | Show hooks, pending records, and config |
| `tempo-cli test` | Dry-run detection against the last commit |
| `tempo-cli test --json` | Same as above, but output raw JSON |

## Supported tools

| Tool | File matching | Process detection | Git trailers |
|------|:---:|:---:|:---:|
| Claude Code | Yes | Yes | Yes |
| Cursor | Yes | Yes | Yes |
| GitHub Copilot | Yes | Yes | Yes |
| Codex | Yes | Yes | — |
| Aider | Yes | Yes | Yes |

File matching reads these local formats:

- **Claude Code:** JSONL session files containing `Edit` or `Write` tool calls.
- **Codex:** rollout JSONL files containing supported patch or shell-write patterns.
- **GitHub Copilot Agent:** VS Code chat-session JSON containing `textEditGroup` entries.
- **Cursor Agent/Composer:** SQLite session databases; requires the `sqlite3` command.
- **Aider:** `.aider.chat.history.md` file-path headings.

A tool being installed does not guarantee a file match. Session availability, recency, and format affect coverage. File matching identifies overlapping paths; it does not attribute individual lines or prove that every suggested edit survived in the commit.

The Git trailers column includes Aider message patterns (`generated by aider` or `aider:`). Codex has no trailer detector. Process detection requires `pgrep` on macOS or Linux.

## Attribution payload

A detected attribution is saved as a JSON file in `.tempo/pending/`. The payload contains metadata, excluding source code, diffs, prompts, and conversation transcripts. Example:

```json
{
  "commit_sha": "a1b2c3d",
  "commit_author": "dev@example.com",
  "repo": "example/repo",
  "timestamp": "2026-02-12T17:08:00Z",
  "detections": [
    {
      "tool": "claude-code",
      "confidence": "high",
      "method": "file-match",
      "files_matched": ["src/auth.ts", "src/auth.test.ts"],
      "files_committed": 5,
      "ai_files": 2,
      "model": "claude-opus-4-6",
      "token_usage": 24500,
      "session_duration_sec": 840
    }
  ]
}
```

## Privacy

Tempo CLI reads supported session files locally to extract attribution metadata. When an API token is configured, it uploads the attribution payload shown above to the configured endpoint.

The payload contains commit identity, timestamp, repository, git author email, detection method and confidence, matched file paths, and optional model or usage metadata. It excludes source contents, diffs, prompts, and conversation transcripts.

This describes Tempo CLI uploads. Entire Checkpoints is a separate integration with different stored session data; see the [AI coding detection methodology](https://usetempo.dev/methodology/ai-coding-detection).

## Configuration

Config is stored at `~/.tempo/config.json`:

```json
{
  "api_token": "tpo_abc123...",
  "endpoint": "https://api.usetempo.dev"
}
```

**Environment variables:**

| Variable | Description |
|----------|-------------|
| `TEMPO_API_ENDPOINT` | Override the API endpoint |
| `TEMPO_SESSION_MAX_AGE` | Session recency window in hours (default: 72) |

## Offline mode

Without an API token, detection still runs and attribution records stay in `.tempo/pending/`; no attribution upload is attempted. Inspect the local records with `cat .tempo/pending/*.json`.
